# Backups

`./portcullis backup` makes a **consistent** backup while everything keeps
running; `--offsite` also uploads it, encrypted, to a
[restic](https://restic.net) repository on another machine or in object
storage. `./portcullis backup verify` proves a backup can be restored, and
`./portcullis restore` puts one back — on the same host or on a new one.

> **A backup is the keys to everything.** It contains `secrets/` — the
> Vault **root token and unseal key** — plus `.env` with every password.
> Whoever has a backup (and, for off-host copies, `BACKUP_PASSWORD`) can
> decrypt the CA and impersonate any user. Local backups are `0700`;
> off-host copies are only as safe as `BACKUP_PASSWORD`.
> **Store `BACKUP_PASSWORD` offline** (password manager, paper in a safe),
> not only in `.env`: if the host is lost, `.env` is lost with it, and the
> off-host backups are useless without the password.

## What is backed up, and how

| Piece | How | Why this way |
|-------|-----|--------------|
| Vault (CA keys, issued-cert records, CRL, AppRole) | raft snapshot (`sys/storage/raft/snapshot`, root token) → `vault.snap` | consistent point-in-time copy; no need to stop Vault |
| Keycloak database | `pg_dump -Fc` → `postgres.dump` | a raw copy of a running Postgres data directory is not consistent |
| LLDAP (`lldap_data`) | files, with every SQLite database copied through SQLite's online backup API → `lldap_data.tar.gz` | consistent while LLDAP runs; keeps `private_key` (password hashing) |
| Hub state (`hub_data`), ACME account + certs (`traefik_acme`) | same → `hub_data.tar.gz`, `traefik_acme.tar.gz` | |
| `.env`, `certs/`, `secrets/`, `config/`, `keycloak/realm-export.json`, `headscale/config.yaml`, `docker-compose.override.yml` | copied | |
| `MANIFEST.json` | format, time, core version, Hub image, sha256 of every file | `verify` and `restore` refuse a backup whose files changed |

A backup is built in `backups/<timestamp>.partial/` and renamed to
`backups/<timestamp>/` when complete. The newest `BACKUP_KEEP_LOCAL`
(default 7) local backups are kept. `portcullis upgrade` makes one first.

## Off-host backups (restic)

Configure the repository in `.env`:

```bash
# Any restic backend the container can reach: s3:, b2:, azure:, gs:, rest:,
# or a local path (e.g. an NFS / USB mount).
BACKUP_REPOSITORY=s3:https://s3.eu-central-1.amazonaws.com/my-bucket/portcullis
# BACKUP_PASSWORD is generated by ./portcullis init — copy it somewhere offline.

# Provider credentials (restic's variable names). BACKUP_<NAME> wins over
# <NAME>, so BACKUP_AWS_* can differ from the AWS_* used for Route53 / ACME.
BACKUP_AWS_ACCESS_KEY_ID=...
BACKUP_AWS_SECRET_ACCESS_KEY=...
# B2_ACCOUNT_ID / B2_ACCOUNT_KEY, AZURE_ACCOUNT_NAME / AZURE_ACCOUNT_KEY,
# GOOGLE_PROJECT_ID, RESTIC_REST_USERNAME / RESTIC_REST_PASSWORD, ...

# Retention applied after every upload (restic forget --prune).
BACKUP_KEEP_DAILY=7
BACKUP_KEEP_WEEKLY=4
BACKUP_KEEP_MONTHLY=6
```

```bash
./portcullis backup --offsite          # local backup, then upload + retention
./portcullis backup --list --offsite   # restic snapshots
```

restic runs in its pinned image (`BACKUP_RESTIC_IMAGE` in
`scripts/lib/backup.sh`) as your user, with a read-only root filesystem and
no capabilities. The repository password and the provider credentials are
handed to the container by variable name, never on a command line. The
first upload initialises the repository. Every snapshot has host
`portcullis`, tag `portcullis` and the path `/portcullis-backup`, so all
runs form one series (deduplicated and incremental).

`sftp:` and `rclone:` repositories are not supported (the container has
neither ssh keys nor rclone); use `rest:` with
[rest-server](https://github.com/restic/rest-server) instead.

## Verify

```bash
./portcullis backup verify                 # off-host: latest snapshot
./portcullis backup verify --snapshot 1a2b3c4d
./portcullis backup verify --local         # newest local backup (or --local DIR)
```

Off-host verification runs `restic check` (reading
`BACKUP_VERIFY_READ_DATA`, default `10%`, of the data), restores the
snapshot into a temporary directory and checks it like a local backup:

- every file matches `MANIFEST.json`; `.env`, the root token and the unseal
  key are present;
- `vault.snap` is a raft snapshot (`meta.json`, `state.bin`, its
  `SHA256SUMS`);
- `postgres.dump` restores into a throwaway Postgres container (no network)
  and contains the Keycloak realms;
- the LLDAP database opens, passes `integrity_check` and has users;
- every volume archive is readable.

Run it regularly (e.g. weekly) — a backup that was never restored is a hope,
not a backup.

## Schedule

The backup has to drive Docker on the host (`docker exec`, throwaway
containers), so it runs from a **systemd timer**, not from a container: a
scheduler container would need the Docker socket, which only the socket
proxies may mount (integration contract §6).

```bash
./portcullis backup schedule --systemd --output /tmp/units
sudo install -m 0644 /tmp/units/portcullis-backup.service /tmp/units/portcullis-backup.timer /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now portcullis-backup.timer
sudo systemctl start portcullis-backup.service    # once now; journalctl -u portcullis-backup
```

The service runs `portcullis backup --offsite` (just `backup` while
`BACKUP_REPOSITORY` is unset) daily at 03:15 (`--on-calendar` to change,
plus up to 30 minutes random delay, catching up after downtime) as the
user who generated it — that user must be allowed to run `docker`.
Afterwards it runs `portcullis status --textfile`. Both publish metrics for
the [monitoring profile](monitoring.md), which alerts when the last
successful local or off-host backup is older than 36 hours.

## Restore

```bash
./portcullis restore --list                     # local backups
./portcullis restore backups/20261031-031500    # a local backup
./portcullis restore --from-offsite             # latest off-host snapshot
./portcullis restore --from-offsite 1a2b3c4d    # a specific one
```

The restore checks the backup's checksums, saves the current `.env`,
`secrets/` and `certs/` to `backups/pre-restore-<timestamp>/`, stops
Portcullis, and then:

1. restores `.env`, `certs/`, config files (an existing `config/` repo is
   left alone);
2. recreates the Postgres and Vault volumes; `pg_restore`s the Keycloak
   database into the fresh Postgres;
3. initialises the fresh Vault with throwaway keys, force-restores the raft
   snapshot (which brings back the original keyring), installs the backed-up
   `secrets/` and recreates Vault, which then auto-unseals with the
   **original** unseal key;
4. restores the LLDAP / Hub / ACME volumes;
5. runs `vault init` (refreshes the enroll AppRole secret and the metrics
   token), starts everything and waits for Vault, Postgres, LLDAP and
   Keycloak.

### On a new host

```bash
git clone https://github.com/porelli/portcullis.git && cd portcullis
export BACKUP_REPOSITORY=s3:https://...  BACKUP_PASSWORD='<from your offline copy>'
export AWS_ACCESS_KEY_ID=... AWS_SECRET_ACCESS_KEY=...   # the provider credentials
./portcullis restore --from-offsite
```

`.env` comes from the backup. Point DNS at the new host; the ACME
certificate is restored too, so Traefik does not have to re-issue it.
