# Portcullis — Claude Code Instructions

## Project Overview

Self-hosted YubiKey authentication gateway. Core stack: Traefik, Keycloak, LLDAP, Vault PKI, oauth2-proxy, group-gate.

This is the **core infrastructure repo**. Related repos:

## Critical Rules

### Documentation

Every code change MUST have corresponding documentation updates:

- **New app template** → add to `porelli/portcullis-templates`, regenerate docs catalog
- **Auth changes** → update manifest `auth` section, update `docs/certificates.md` or `group-gate/group-gate-map.conf`
- **Hub UI changes** → make in `porelli/portcullis-hub`, update `docs/operations/hub.md` in docs repo
- **CI/test changes** → update `docs/operations/testing.md` in docs repo
- **Group model changes** → update `docs/operations/groups.md` in docs repo

### App Templates

Templates live in `porelli/portcullis-templates` (not this repo). The Hub auto-clones them on first startup.

- Forward-auth apps MUST use middleware: `portcullis-auth@docker,portcullis-groups@docker`
- Native OIDC apps should NOT use forward-auth
- Each app runs as its own compose project (`portcullis-<app-id>`)
- Apps connect via `portcullis-proxy` network, NOT `portcullis`
- Per-app `.env` files generated by Hub

### Group Model

- Access groups: `users_<app>` — required to access the app
- Admin groups: `admin_<app>` — grants admin privileges
- Core infrastructure requires `lldap_admin` group (`enroll.<domain>/self` is the one exception: any signed-in user, own cert only)
- Groups: LLDAP → Keycloak (LDAP sync) → oauth2-proxy → group-gate
- **Identity = LLDAP username, never the email** (users can edit their own mail in LLDAP): Keycloak LDAP `trustEmail=false`, oauth2-proxy injects `preferred_username` as `X-Auth-Request-User`/`X-Forwarded-User`/`X-Auth-Request-Preferred-Username` (its session user is `sub`; alpha `userIDClaim` is just an alias of `emailClaim` — never use it) + `insecureAllowUnverifiedEmail`; group-gate reads the user ONLY from `X-Auth-Request-Preferred-Username` (denies without it) and returns `X-Forwarded-User` = username and `X-Forwarded-Email` = email. Every identity header must be in the forward-auth middlewares' `authResponseHeaders` (that is what strips client copies). Details: `docs/hardening.md`

### Testing

- Core infra CI: `.github/workflows/ci.yml` (this repo)
- Unit tests (no containers): `python3 -m pytest -q tests/`, `bash tests/test_cli.sh`, `bash tests/test_shell_libs.sh`, `cd enroll && go test ./...`
- Lint: `shellcheck -S warning portcullis scripts/lib/*.sh tests/*.sh`, `actionlint`
- CI drives everything through `./portcullis` and runs `<cmd> --help` for every command listed by `./portcullis help`
- Client-cert revocation is enforced by group-gate, so routers need `client-headers@file` BEFORE `portcullis-groups@docker`. Vault pki_int: `auto_rebuild` + `enable_delta` (delta rebuilt every 1m) — revocations made in Vault directly appear only in the delta CRL until the next full rebuild, so group-gate (`GATE_CRL_URL` + `GATE_DELTA_CRL_URL`) and Keycloak (`crl-relative-path` with `##`) read both; `cert revoke` rotates the full CRL
- oauth2-proxy endpoints are routed only on `auth.<domain>` (step-up = `https://auth.<domain>/oauth2/start?...&rd=<app>`): never add a host-less router — Traefik serves it with default TLS options and answers 421 on tiered hosts (CI rejects rules without `Host(`)
- Browser e2e (CI job `e2e`, needs the whole stack): `tests/e2e/e2e_login.py` (Playwright, pinned in `tests/e2e/requirements.txt`, CDP virtual WebAuthn authenticator). Not collected by pytest. Screenshots/traces/logs are uploaded on failure
- Monitoring config: CI runs `promtool check config --syntax-only`, `promtool check rules`, `promtool test rules monitoring/prometheus/tests/alerts_test.yml`, `amtool check-config` on every generated receiver variant, `blackbox_exporter --config.check`. Rule tests need `exp_annotations` and samples at least every 5m (lookback)
- CI build-and-test ends with backup → `backup verify --local` → restic (local repo) `--offsite` x3 (restic ≥0.17 keeps oldest+newest same-day snapshots) → `backup verify` → wipe everything (`down -v`, `.env`, `secrets/`, `certs/`) → `restore --from-offsite` → CA / cert records / revocations / Keycloak / LLDAP must match. The e2e job runs with `COMPOSE_PROFILES=monitoring` (targets up, probes, rules, Grafana gated)
- Local verification without Docker: `docker compose -f docker-compose.yml --env-file <generated .env> config -q` (generate one with `PORTCULLIS_ROOT=/tmp/x ./portcullis init --env-only --non-interactive --domain ci.example.org --dns-provider none`)
- Per-app template tests live in `porelli/portcullis-templates` (`tests/apps/<app>.sh`, `.github/workflows/test-apps.yml`)

### Admin CLI

- **One entrypoint: `./portcullis`** (bash, `set -euo pipefail`). `./portcullis help` lists every command, `./portcullis <cmd> --help` documents it. Logic lives in `scripts/lib/<area>.sh` (common, network, vault, pki, certs, keycloak, dns, config, status, monitoring, backup, stack); the entrypoint sources them all and dispatches to `cmd_<name>`. There are no other scripts — don't add standalone ones.
- New command: add `cmd_<x>` + `help_<x>` in the right lib, list it in `help_main`, extend `tests/test_cli.sh`. `--help` must work without `.env`/Docker; argument errors exit 2.
- `.env` is **parsed, never sourced**; shell environment wins over `.env`, like docker compose. Edit it with `env_set` (in place — it may be a symlink into `config/`). The Hub never sees it: `hub_env_write` generates `secrets/hub/core.env` (whitelisted vars only, never `CORE_SECRETS`), mounted read-only as the Hub's `/project/.env`.
- Files a non-root container reads stay operator-owned with the container's GID (`ct_group_read`: 0640 / dirs 0750; `ct_own` uses a throwaway root container when not root). UIDs/GIDs are `CT_*` in `common.sh` and must match `user:` / the images (vault 100:1000, hub 10001, enroll 10002, group-gate 10003, Traefik root/group 0). `stack_prepare` → `secrets_fix_perms` repairs them on every run.
- Secrets never go on argv: request bodies via stdin, bearer tokens via `curl -H @<(...)`, Vault secrets via `key=-`.
- No migration/back-compat code: the project has no installs to upgrade from. `portcullis upgrade` = backup, pull, re-run the idempotent steps, `up`.

### Deployment

- First install: `./portcullis init`; afterwards `./portcullis up|down|upgrade|status`
- Every secret (`POSTGRES_PASSWORD`, `KEYCLOAK_ADMIN_PASSWORD`, `LLDAP_*`, `FORWARD_AUTH_*`, `HUB_PROXY_SECRET`) is generated by `init` and required by compose (`${VAR:?}`) — never add a default
- Vault runs in server mode (raft, data in `/vault/file`) and auto-unseals from `secrets/`; the CLI reads the root token from `secrets/vault-init.json` (or `VAULT_TOKEN`). Never add a default/dev token.
- `portcullis-proxy` has fixed IPAM (`PORTCULLIS_PROXY_SUBNET`/`_IP_RANGE`); Traefik is pinned to `PORTCULLIS_TRAEFIK_IP` — header-auth apps trust only that IP
- `templates/` must exist before `up` (`init`/`up`/`upgrade` create it); the Hub fills it
- Hub image: `${HUB_IMAGE:-ghcr.io/porelli/portcullis-hub:edge}` (edge = main; releases are semver tags). It needs `HUB_PROXY_SECRET` (contract §5): the `hub-proxy-secret@docker` headers middleware injects it, placed AFTER the forward-auth middlewares so the secret never reaches oauth2-proxy / group-gate
- **No service mounts `/var/run/docker.sock` except `socket-proxy-traefik` (read-only) and `socket-proxy-hub`** (contract §6), each on its own internal network. Endpoint sets and limits: `docs/hardening.md`
- Every core image is pinned `tag@sha256:…` (get the index digest from the registry, e.g. `docker manifest inspect` / registry API); every service has `no-new-privileges`, `cap_drop: ALL`, mem/pids limits; read-only root FS + non-root where possible (exceptions in `docs/hardening.md`). CI enforces pins, the socket rule and the hardening baseline
- Keycloak sits on `portcullis-auth` (internal, fixed IPAM `PORTCULLIS_AUTH_*`) with Traefik; `--proxy-trusted-addresses=$PORTCULLIS_AUTH_TRAEFIK_IP` — proxy headers incl. the forwarded client cert (X.509 login, `traefik` lookup provider, `client-cert-pem@file`) are trusted only from there. All `auth.<domain>` routers use `authaware@file`
- Client certs: `CLIENT_CERT_TTL` (default 720h); `pki setup` rewrites the Vault role every run. Self-service renewal at `enroll.<domain>/self` (router `enroll-self`, `portcullis-self@docker` = group-gate `/authenticated`)
- Hub auto-clones templates from `porelli/portcullis-templates`; the Hub gets no LLDAP credentials

### Backups, monitoring, releases

- `portcullis backup` is **logical and online**: Vault raft snapshot (root token, API), `pg_dump -Fc`, SQLite online backup inside the lldap/hub/acme volume archives (run as the volume owner's uid), plus `.env`, `certs/`, `secrets/`, `config/`, `MANIFEST.json` (sha256 of every file). Never stop services for it. `--offsite` = restic in its pinned image (`BACKUP_RESTIC_IMAGE`), as the operator uid; `BACKUP_PASSWORD` + provider creds passed by env NAME in a subshell (`BACKUP_<NAME>` overrides `<NAME>`, so Route53 `AWS_*` don't leak into restic or vice versa). `BACKUP_PASSWORD` is generated by init/upgrade (`BACKUP_SECRETS`, not a compose secret) and must never be rotated
- `restore` restores the raft snapshot into a FRESH Vault (temp init → `snapshot-force` → install backed-up `secrets/` → recreate → auto-unseal with the original key) and `pg_restore`s into a fresh Postgres; it refuses backups whose checksums don't match
- Scheduling is a systemd timer (`backup schedule --systemd`), not a container: a scheduler container would need the Docker socket (contract §6)
- Monitoring = compose profile `monitoring` (`COMPOSE_PROFILES=monitoring` in `.env`). `monitoring_prepare` (in `stack_prepare`) writes `secrets/monitoring/{prometheus,alertmanager}` (group 65534) and `grafana/` (group 472); `vault init` keeps the Prometheus token (policy `portcullis-metrics`, `vault/policies/metrics.hcl`). Metrics endpoints stay internal (Traefik `:8082` entrypoint, group-gate `/metrics`, Keycloak `:9000`). `metrics` is a core group-gate subdomain (`lldap_admin`). The CLI publishes textfile metrics in `monitoring/textfile/` (`backup`, `status --textfile`)
- Releases: `vX.Y.Z` tags only, `release.yml` (preflight: CHANGELOG section + `HUB_IMAGE` default = released Hub tag@digest; then `ci.yml` via `workflow_call`; then notes + `portcullis-X.Y.Z.tar.gz` with `VERSION` + sha256). `portcullis version` = `VERSION` file, else `git describe`. Keep `CHANGELOG.md` (Keep a Changelog) `Unreleased` up to date
- Supply chain: every image `tag@sha256` in all compose files/profiles, CLI constants and workflows; actions pinned by full commit SHA with `# vX.Y.Z`; CI enforces all of it. CI caches (`.github/actions/cached-images` docker-save tarballs, Go module/build cache, buildx `type=gha` layers for enroll, pip + Playwright browsers) are restored everywhere but saved only on pushes to main; cached images are never trusted by name — every ref is re-bound by a pinned-digest `docker pull` (manifest-only when the content matches). `.github/dependabot.yml` covers compose, enroll Dockerfile, gomod, actions, e2e pip (not the CLI/workflow inline images)
