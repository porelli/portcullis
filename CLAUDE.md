Self-hosted YubiKey authentication gateway. Core stack: Traefik, Keycloak, LLDAP, Vault PKI, oauth2-proxy, group-gate, domains (enrolled extra domains).

## Critical Rules

### Documentation

All documentation lives in the docs site repo `porelli/portcullis-docs` (published at https://porelli.github.io/portcullis-docs/); its `CLAUDE.md` maps every kind of change to the page to update. This repo keeps only `README.md` (overview + links to the site). `docs/*.md` here are **one-line pointers** to the published pages (kept so old links resolve): never add content to them or new files to `docs/`; code comments that say "see docs/X.md" mean the page that pointer links to.

Every code change MUST have corresponding documentation updates:

- **New app template** → add to `porelli/portcullis-templates`, regenerate docs catalog
- **Auth changes** → update manifest `auth` section, `docs/setup/certificates.md` / `docs/operations/auth-policies.md` in the docs repo, or `group-gate/group-gate-map.conf`
- **Hardening, socket proxies, secrets ownership, header trust** → `docs/operations/hardening.md` in docs repo (authoritative per-service table)
- **Backups / monitoring** → `docs/operations/backups.md` / `docs/operations/monitoring.md` in docs repo
- **New or changed `./portcullis` command or option** → `docs/operations/cli.md` in docs repo
- **Hub UI changes** → make in `porelli/portcullis-hub`, update `docs/operations/hub.md` in docs repo
- **CI/test changes** → update `docs/operations/testing.md` in docs repo
- **Group model changes** → update `docs/operations/groups.md` in docs repo

### App Templates

Templates live in `porelli/portcullis-templates` (not this repo). The Hub auto-clones them on first startup.

- Forward-auth apps MUST use middleware: `portcullis-auth@docker,portcullis-groups@docker`
- Native OIDC apps should NOT use forward-auth
- Each app runs as its own compose project (`portcullis-<app-id>`)
- Apps connect via `portcullis-proxy` network, NOT `portcullis`
- Per-app `.env` files generated by Hub

### Group Model

- Access groups: `users_<app>` — required to access the app
- Admin groups: `admin_<app>` — grants admin privileges
- Core infrastructure requires `lldap_admin` group (`enroll.<domain>/self` is the one exception: any signed-in user, own cert only)
- Groups: LLDAP → Keycloak (LDAP sync) → oauth2-proxy → group-gate
- **Identity = LLDAP username, never the email** (users can edit their own mail in LLDAP): Keycloak LDAP `trustEmail=false` and `cachePolicy=NO_CACHE` (export + `keycloak configure`'s `_kc_ldap_patch`: LLDAP group/attribute changes reach the next token), oauth2-proxy injects `preferred_username` as `X-Auth-Request-User`/`X-Forwarded-User`/`X-Auth-Request-Preferred-Username` (its session user is `sub`; alpha `userIDClaim` is just an alias of `emailClaim` — never use it) + `insecureAllowUnverifiedEmail`; group-gate reads the user ONLY from `X-Auth-Request-Preferred-Username` (denies without it) and returns `X-Forwarded-User` = username and `X-Forwarded-Email` = email. Every identity header must be in the forward-auth middlewares' `authResponseHeaders` (that is what strips client copies). Details: docs repo `docs/operations/hardening.md`

### Admin CLI

- **One entrypoint: `./portcullis`** (bash, `set -euo pipefail`). `./portcullis help` lists every command, `./portcullis <cmd> --help` documents it. Logic lives in `scripts/lib/<area>.sh` (common, network, vault, pki, certs, keycloak, users, domains, dns, config, status, monitoring, backup, stack); the entrypoint sources them all and dispatches to `cmd_<name>`. There are no other scripts — don't add standalone ones.
- New command: add `cmd_<x>` + `help_<x>` in the right lib, list it in `help_main`, extend `tests/test_cli.sh`. `--help` must work without `.env`/Docker; argument errors exit 2.
- `.env` is **parsed, never sourced**; shell environment wins over `.env`, like docker compose. Edit it with `env_set` (in place — it may be a symlink into `config/`). The Hub never sees it: `hub_env_write` generates `secrets/hub/core.env` (whitelisted vars only, never `CORE_SECRETS`), mounted read-only as the Hub's `/project/.env`.
- Files a non-root container reads stay operator-owned with the container's GID (`ct_group_read`: 0640 / dirs 0750; `ct_own` uses a throwaway root container when not root). UIDs/GIDs are `CT_*` in `common.sh` and must match `user:` / the images (vault 100:1000, hub 10001, enroll 10002, group-gate 10003, domains 10004 (+ group 10001 for the shared API secret), Traefik root/group 0). enroll, group-gate and domains are built locally (`<dir>/Dockerfile`, images `portcullis-enroll` / `portcullis-group-gate` / `portcullis-domains`); backups run their SQLite helpers in `portcullis-group-gate` (no `ENTRYPOINT`, so `python3 -c` works). `stack_prepare` → `secrets_fix_perms` repairs them on every run. Named volumes shared by several services (`hub_data`: Hub rw + group-gate ro) are created and chowned by `volume_own` in `stack_prepare`, because whichever container starts first creates the volume and a missing mountpoint in its image leaves it root-owned.
- Secrets never go on argv: request bodies via stdin, bearer tokens via `curl -H @<(...)`, Vault secrets via `key=-`, jq via `--rawfile` / `env.X` (never `--arg x "$(cat f)"`). `tests/test_cli.sh` greps for it; reviewed exceptions carry `secret-argv-ok`. `portcullis-hub` can't sign in (federation filter `(!(uid=portcullis-hub))`, group-gate `GATE_DENY_USERS`)
- No migration/back-compat code: the project has no installs to upgrade from. `portcullis upgrade` = backup, pull, re-run the idempotent steps, `up`, then `hub_policy_check` and `hub_sources_sync` (status.sh: SIGHUP to the Hub once its `<data>/source-sync.json` is newer than the container — an older Hub would die on SIGHUP —, then prints each source's result; never fails the run).
- Users / groups deleted in LLDAP leave Keycloak: LDAP federation `removeInvalidUsersEnabled` + `fullSyncPeriod` 3600 + `editMode` READ_ONLY (`_kc_ldap_patch`), group mapper `drop.non.existing.groups.during.sync` (`_kc_group_mapper_patch`); Keycloak's sync never removes users — a lookup does (the Hub lists all users every 15 min). `./portcullis restore` refuses to go on past the volume restore (Postgres + Vault up, nothing else) when LLDAP has no users besides admin/portcullis-hub (or no users.db) but the restored Keycloak DB has federated users (`_restore_lldap_guard`, `--allow-empty-lldap` overrides). CI step "Test users and groups deleted in LLDAP leave Keycloak" (also: LLDAP down removes nothing; admin/testuser keep their Keycloak ids; `portcullis-hub` stays in LLDAP, never in Keycloak).

### Deployment

- First install: `./portcullis init`; afterwards `./portcullis up|down|upgrade|status`
- Every secret (`POSTGRES_PASSWORD`, `KEYCLOAK_ADMIN_PASSWORD`, `LLDAP_*`, `FORWARD_AUTH_*`, `HUB_PROXY_SECRET`) is generated by `init` and required by compose (`${VAR:?}`) — never add a default
- Vault runs in server mode (raft, data in `/vault/file`) and auto-unseals from `secrets/`; the CLI reads the root token from `secrets/vault-init.json` (or `VAULT_TOKEN`). Never add a default/dev token.
- `portcullis-proxy` has fixed IPAM (`PORTCULLIS_PROXY_SUBNET`/`_IP_RANGE`); Traefik is pinned to `PORTCULLIS_TRAEFIK_IP` — header-auth apps trust only that IP
- `templates/` must exist before `up` (`init`/`up`/`upgrade` create it); the Hub fills it
- `appfiles/` likewise (`stack_prepare`: 0750, chowned to 10001); the Hub writes settings data files there (`<id>/<name>/<name>.json`, contract §13.7); not backed up (the Hub regenerates it from state)
- Hub image: `${HUB_IMAGE:-ghcr.io/porelli/portcullis-hub:edge}` (edge = main; releases are semver tags). It needs `HUB_PROXY_SECRET` (contract §5): the `hub-proxy-secret@docker` headers middleware injects it, placed AFTER the forward-auth middlewares so the secret never reaches oauth2-proxy / group-gate
- **No service mounts `/var/run/docker.sock` except `socket-proxy-traefik` (read-only) and `socket-proxy-hub`** (contract §6), each on its own internal network. Endpoint sets and limits: docs repo `docs/operations/hardening.md`
- Every core image is pinned `tag@sha256:…` (get the index digest from the registry, e.g. `docker manifest inspect` / registry API); every service has `no-new-privileges`, `cap_drop: ALL`, mem/pids limits; read-only root FS + non-root where possible (exceptions in docs repo `docs/operations/hardening.md`). CI enforces pins, the socket rule and the hardening baseline
- Keycloak sits on `portcullis-auth` (internal, fixed IPAM `PORTCULLIS_AUTH_*`) with Traefik; `--proxy-trusted-addresses=$PORTCULLIS_AUTH_TRAEFIK_IP` — proxy headers incl. the forwarded client cert (X.509 login, `traefik` lookup provider, `client-cert-pem@file`) are trusted only from there. All `auth.<domain>` routers use `authaware@file`
- Client certs: `CLIENT_CERT_TTL` (default 720h); `pki setup` rewrites the Vault role every run. Self-service renewal at `enroll.<domain>/self` (router `enroll-self`, `portcullis-self@docker` = group-gate `/authenticated`)
- Hub auto-clones templates from `porelli/portcullis-templates`. The Hub's LLDAP access is its own service account `portcullis-hub` (`lldap_admin`), reconciled by `init`/`up`/`upgrade` (`lldap_service_account`, scripts/lib/users.sh); credentials are FILES `secrets/hub/lldap/{username,password}` → `/run/portcullis/lldap` (never env vars). Contract §9
- **Sign-in is passkey-only** (no password in `portcullis-universal`): LoA 1 = cert or passkey, LoA 2 = allow-access (same touch), LoA 3 = cert; oauth2-proxy default `acr_values=hwk`; group-gate's step-up has no `prompt=login`. First passkeys come ONLY from one-time setup links: `./portcullis invite <user>` (exec into enroll, loopback 8446, the one way to invite `admin`) or the Hub (`POST enroll:8444/internal/invites`, bearer `secrets/enroll/invite-api-secret` = Hub's `/run/portcullis/invite/secret`, refuses `admin`/`portcullis-hub` and every member of `lldap_admin`, `lldap_password_manager` and the core-console groups — LLDAP lookup, fail closed; admins only via the CLI). enroll is the hidden Keycloak IdP `portcullis-invite` (public `/invite/*`, back-channel 8445 unrouted; links existing users only; post-broker flow = only `portcullis-forward-auth`, then LoA 2 + amr hwk) and sets `webauthn-register-passwordless` via service account `portcullis-enroll` on redeem. Invites live in enroll's memory (restart = re-issue). Login theme `portcullis` (`keycloak/themes/portcullis`: keycloak.v2 + a copy of `webauthnRegister.js` that sets a unique label "Security key <date time>" without the label prompt — stock Keycloak's fixed default label made a user's second key fail with "Device already exists with the same name"; keep the copy in sync with the Keycloak image). `portcullis invite --replace-keys` = lost key (delete keys + sign out first); without it a re-invite adds a spare key Keycloak 26.8 cannot enrol a passkey inside a flow (`WebAuthnPasswordlessAuthenticatorFactory.isUserSetupAllowed()` = false)
- `keycloak configure` rebuilds a top-level flow of `realm-export.json` whenever its tree changed (`[sync <hash>]` in the description; `_kc_sync_flow`): edit flows in the export only. Realm `sslRequired=external` (the invite IdP's http back-channel). The invite IdP lives in `keycloak/invite-idp.json`, NOT the realm export: Keycloak checks http URLs by resolving the host, and at the first start's import `enroll` may not resolve (import aborts); configure creates it once enroll runs
- Keycloak `/admin` routes use `portcullis-auth-console` (no `Authorization` in `authResponseHeaders`, or the console's own bearer token is replaced); `/resources/` has its own router (general rate limit). `lldap_admin` = `realm-admin` of the portcullis realm (console with the passkey session)
- `people.<domain>` = the Hub's directory listener (`HUB_PEOPLE_ADDR` :8889, Traefik service `hub-people`; router chain client-headers → portcullis-auth → portcullis-groups → hub-proxy-secret → security-headers), open to every signed-in user (`people=*`); `directory.<domain>` only redirects there (LLDAP has no SSO; its own UI is break-glass via `./portcullis lldap-ui`). Every forwardAuth middleware carries `authResponseHeadersRegex: ^X-Forwarded-Attr-` (that is what strips client copies — Traefik can't delete headers by prefix); routers without forwardAuth don't strip them, so their backends must not trust them
- **Domains service** (`domains/`, contract §12): Go, lego v4 as a library (DNS-01), libdns providers (cloudflare, porkbun, route53, digitalocean, hetzner — the `dns setup` list), filippo.io/age. API `:8080` on `portcullis-domains` (members: domains + Hub; bearer `secrets/domains/api-secret`, group 10001, also the Hub's `/run/portcullis/domains/api-secret`), egress on `domains-egress`, never routed. Everything it keeps (credentials, ACME account, per-domain state, certs + keys) is ONE age-encrypted file `domains_data/store.age` (key `secrets/domains/age.key`, generated by `domains keygen` in the image, offline; backed up encrypted, `BACKUP_FILE_VOLUMES`). Every libdns call goes through a redacting wrapper (provider errors may echo tokens); `last_error`, logs and API answers never carry credentials. Generations are never reused (re-enroll can't receive stale work); records a step creates are committed by `EnrollID` (survive a token replacement); DELETE and token replacement wait for a running records step (bounded by the request, else 503) and DELETE removes the tracked records in every zone. A stored name failing `checkName` gets no work (error); an issued cert that `servable()` refuses is not stored (fail + backoff); served certs also need CN ∈ {"", d, *.d}. Records set to other addresses than configured are redone at start (`AppliedIPv4/6`). Provider HTTP is bounded (`setHTTPDefaults`: dial/TLS/header timeouts on `http.DefaultTransport`, wrapped in `timeoutTransport` — a 2-min per-request deadline incl. the body, for libraries that build their own `http.Client{}`; cloudflare client timeout). DELETE budget: records-step wait 90 s + record removal 60 s < API WriteTimeout 3 min < Hub client 4 min; route53's config is pre-loaded so its `log.Fatalf` can't fire (+ `AWS_*_FILE=/dev/null`, no IMDS in the Dockerfile); a panicking provider is recovered. Credential values ≥ 8 chars (redaction). The API accepts only connections addressed to `portcullis-domains` (fixed subnet `PORTCULLIS_DOMAINS_SUBNET`, default 172.31.252.0/28 → `DOMAINS_API_SUBNET`) or loopback: never from Traefik on `portcullis-certs`. `libdns/hetzner` v1.0.0 uses Hetzner's legacy DNS API (dns.hetzner.com), as `dns setup` does `scripts/lib/domains.sh` (`domains_prepare` in `stack_prepare`): api-secret, age key, the certificate endpoint's private CA (10 y) + server (`DNS:domains`) / client certs (valid until the CA expires, ECDSA P-256; renewed < 30 d, CA < 1 y → all; `up`/`upgrade` then restart domains, wait healthy, then traefik), public IPs (`PORTCULLIS_PUBLIC_IPV4/_IPV6` from .env always win; else `public_ip_detect` in network.sh, shared with `dns setup`: HTTPS only, ≥ 2 services must agree, global unicast only; skipped while `domains enrolled` (in the running container) says 0; a failed or skipped lookup keeps `secrets/domains/last-public-ipv4` / `-ipv6`; the result goes to `secrets/domains/public-ips.env`, the domains service's `env_file` (not `environment:`), so a manual `docker compose up` gets it; with the IPv4 unknown the service keeps records it set before (no records step, check against `AppliedIPv4/6`) and still renews)
- Enrolled domains' certificates reach Traefik through its HTTP provider polling the domains service (contract §12.4: inline PEM `tls.certificates` only, on an internal network of Traefik + domains, client-cert auth from files; static config ships with the domains service). Not a shared volume under the file provider (it doesn't watch subdirectories) and never a sidecar in Traefik's PID namespace (it could read Traefik's environment, DNS tokens included). Extra-domain routers carry `tls.options` (no cert resolver), so Traefik's ACME never tries their hosts
- Invite post-broker flow `portcullis-invite-session` admits only clients with the marker scope `portcullis-invite-client` (positive client-scope condition, then deny unless admitted, then LoA 2): `keycloak configure` keeps it a default scope of `portcullis-forward-auth` only (removed from every other client and the realm defaults), so a setup link can't sign in to a Hub access-role client (contract §8). `keycloak configure` keeps the Hub's `https://<host>/oauth2/callback` redirect URIs on `portcullis-forward-auth` (`_kc_fwd_patch`)
- oauth2-proxy `OAUTH2_PROXY_COOKIE_REFRESH=1m`: forward-auth sessions re-validate with Keycloak every minute, so a removal or a Keycloak logout takes effect within ~1 min (sessions end at Keycloak's idle/max limits)
- Portal at `https://<domain>/`: group-gate `/portal` (router `portal`, replacePath), reads the Hub's `portal-apps.json` (contract §10) from `hub_data`

### Backups, monitoring, releases

- `portcullis backup` is **logical and online**: Vault raft snapshot (root token, API), `pg_dump -Fc`, SQLite online backup inside the lldap/hub/acme volume archives (run as the volume owner's uid), plus `.env`, `certs/`, `secrets/`, `config/`, `MANIFEST.json` (sha256 of every file). Never stop services for it. `--offsite` = restic in its pinned image (`BACKUP_RESTIC_IMAGE`), as the operator uid; `BACKUP_PASSWORD` + provider creds passed by env NAME in a subshell (`BACKUP_<NAME>` overrides `<NAME>`, so Route53 `AWS_*` don't leak into restic or vice versa). `BACKUP_PASSWORD` is generated by init/upgrade (`BACKUP_SECRETS`, not a compose secret) and must never be rotated
- `restore` first stops the Hub (`dc stop hub`, so nothing restarts an app meanwhile; any later abort starts it again before failing), then takes down (`docker compose -p <project> down`, volumes kept, from an empty directory) every non-core compose project with a container mounting `hub_secrets` (the file-sharing apps): Docker can't remove a volume a container references; a failed down or a container left aborts before anything changes (`_restore_stop_secret_apps`); the projects are listed at the end and NOT started again (their credentials were voided; the Hub's drift shows them down). It restores the raft snapshot into a FRESH Vault (temp init → `snapshot-force` → install backed-up `secrets/` → recreate → auto-unseal with the original key) and `pg_restore`s into a fresh Postgres; it refuses backups whose checksums don't match
- Scheduling is a systemd timer (`backup schedule --systemd`), not a container: a scheduler container would need the Docker socket (contract §6)
- Monitoring = compose profile `monitoring` (`COMPOSE_PROFILES=monitoring` in `.env`). `monitoring_prepare` (in `stack_prepare`) writes `secrets/monitoring/{prometheus,alertmanager}` (group 65534) and `grafana/` (group 472); `vault init` keeps the Prometheus token (policy `portcullis-metrics`, `vault/policies/metrics.hcl`). Metrics endpoints stay internal (Traefik `:8082` entrypoint, group-gate `/metrics`, Keycloak `:9000`). `metrics` is a core group-gate subdomain (`lldap_admin`). The CLI publishes textfile metrics in `monitoring/textfile/` (`backup`, `status --textfile`)
- Releases: `vX.Y.Z` tags only, `release.yml` (preflight: CHANGELOG section + `HUB_IMAGE` default = released Hub tag@digest; then `ci.yml` via `workflow_call`; then notes + `portcullis-X.Y.Z.tar.gz` with `VERSION` + sha256). `portcullis version` = `VERSION` file, else `git describe`. Keep `CHANGELOG.md` (Keep a Changelog) `Unreleased` up to date
- Dependencies: prefer mature, maintained libraries (MIT/BSD/Apache-2.0/MPL-2.0, latest stable) over hand-rolled protocol/codec code; pinned in `enroll/go.mod`+`go.sum`, `domains/go.mod`+`go.sum`, `mcp-gate/go.mod`+`go.sum` and `group-gate/requirements.txt` (exact versions + hashes, `--require-hashes`, wheels only)
- Supply chain: every image `tag@sha256` in all compose files/profiles, CLI constants and workflows; actions pinned by full commit SHA with `# vX.Y.Z`; CI enforces all of it. CI caches (`.github/actions/cached-images` docker-save tarballs, Go module/build cache, buildx `type=gha` layers for enroll and group-gate, pip + Playwright browsers) are restored everywhere but saved only on pushes to main; cached images are never trusted by name — every ref is re-bound by a pinned-digest `docker pull` (manifest-only when the content matches). `.github/dependabot.yml` covers compose, enroll + group-gate + domains Dockerfiles, gomod (enroll, domains, mcp-gate), actions, group-gate + e2e pip (not the CLI/workflow inline images)
